# Frontend refinement and recovery verification

The frontend follows `spikes/ui/quitclaim-v5.html`. The warm paper/ink/orange palette, dithered position artwork, rolling numbers, and dither charts remain. The original reference and vendored UI files are unchanged.

## Design changes

- The handover story now has five selectable steps, dithered nonce states, title ownership, and the seller's retained withdrawal. Accounts, nonce, amount, and transaction links come from the published heist evidence.
- The story advances while visible. Selecting a step pauses it, and an explicit pause/play control is available. Reduced-motion preferences stop automatic progression and shader motion.
- Sell and lease explanations use v5's dithered schedule bars. These explain the two control models; they are not quoted financial positions.
- Responsive type sizes and a second navigation row fix the previous mobile overflow. The lot's price and actions appear before its chart on mobile while desktop retains its two columns.
- Financial counters start at the actual balance and retain rolling updates. This removes the initial zero without replacing the dither component.

Visual checks covered light/dark views and 375px layouts. Browser measurements found no horizontal overflow on home, market, lot 0, portfolio, or mint; before the changes, home overflowed by 116px and the lot page by 26px. A second check inspected the restored mobile story in the shared preview and confirmed no positive horizontal overflow.

This is a focused refinement of the existing identity, not a new dashboard design or a claim of award readiness. Individual third-party wallet approval interfaces and a full accessibility audit remain outside these checks.

## Recovery state

Mint and cash-out recovery use Zustand persist with validated storage. Existing raw records remain readable. New writes use a versioned envelope. Malformed and unknown-version records block reads without being discarded. Each operation retains its own storage key, avoiding writes to unrelated lots overwriting one another.

TanStack Query continues to own chain and API data. The custom window event is removed. A single native `storage` listener synchronizes persisted state across browser tabs. Signing still requires successful persistence first. Cash-out records remain local to a browser profile; cross-device recovery has not been added.

## Verification

- `bun run verify`: passes ABI, TypeScript, TS tests, 106 Rust contract tests, and 4 deployed-WASM Sandbox tests.
- `bun run fmt:check`: passes.
- `bun run --cwd apps/web build`: passes.
- The complete real-signer browser scenario passes in about three minutes: mint, reload recovery, list, buy, lease, withdrawal, surrender, return of control, and a Tidepool cash-out reaching SUCCESS after reload.
- `bun run test:browser recovery.pw.ts`: all three no-funds browser tests pass. They cover legacy migration and reload, invalid/future-version preservation, and reactive cross-tab writes and removal.
- The earlier live browser attempt failed during example-stream setup on a FastNEAR rate limit. No swap was started by that attempt. Closing background design tabs removed unnecessary RPC polling before the passing rerun.

No NEAR contract source, contract account, finality, or deployment changed during this pass. No freeze was attempted. See [the serverless proposal](../DEPLOYMENT.md) for the hosting recommendation and work still needed for durable sponsorship and settlement.
